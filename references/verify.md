# 核验

交接的价值全在"可复核"上。这一份讲三件事：什么算验过、怎么发现现场过期、怎么识破听起来像完成的话。

## 一、三态

| 态 | 必须满足 | 典型证据 |
| --- | --- | --- |
| **已验** | 命令真跑过，输出看过，结论和输出对得上 | `node --test` 12 通过 / 打开设置页看到三项 / `文件:行` 与描述一致 |
| **未验** | 只写了代码、只读了文档、只凭经验推断 | 「未验」+ 要跑什么才算完 |
| **放弃** | 试过并且知道为什么不通 | 失败现象 + 原因，写进「已排除」 |

判据只有一条：**换个人照着这条能不能复现出同样的结论？**

常见误判：

- 跑过命令但没看输出 → 未验。
- 单元测试过了，但没开过真实界面 → 未验（写明缺一次手动确认）。
- 文档/上一个人说这样行 → 未验。
- 「之前这样是可以的」 → 未验（环境可能已经变了）。

## 二、什么算跑过

一条完整证据要三样：

1. **命令本身**，能复制粘贴
2. **结果摘要**，通过几个 / 报什么错 / 关键数字
3. **工作目录**，换个目录结果可能不同

```bash
# 这样写
在 F:/AI服务/awu-ui 跑 `node scripts/slop-scan.mjs examples` → 59 处，退出码 1

# 不要这样写
扫描器测试通过
```

## 三、现场过期：四种情况

`check` 比对四样东西，各有一种处置：

| 过期 | 怎么发现 | 处置 |
| --- | --- | --- |
| **HEAD 前进** | 交接里的 `head` ≠ 当前短 SHA | 看新提交动了什么；若涉及「下一步」的文件，先读 diff 再动手 |
| **分支变了** | `branch` 不一致 | 停。确认是不是有人切分支在别处做同一件事 |
| **工作区脏了** | 交接说干净，现在有改动 | 逐文件看；来路不明就不要提交，也不要 stash |
| **文件不见了** | 「下一步」里的路径不存在 | 有人重构或删除了；先找替代路径，找不到就问 |

`repo` 路径本身不存在（换机器、挪目录）时，`check` 只能做格式校验，会明说「无法核验现场」——这时把整份交接降级成参考，重新跑一遍坐标命令。

## 四、听起来像完成的话

看到下面这些，默认标未验：

1. 「应该可以了」
2. 「理论上没问题」
3. 「照着文档写的」
4. 「之前这样是行的」
5. 「逻辑上是对的」
6. 「只差联调」
7. 「已经改好，还没看效果」

真正的完成长这样：**命令 + 数字 + 一个具体观察**。例如「`node --test` 12 通过；打开 `examples/before.html`，top-label 命中从 3 降到 2」。

## 五、接手的核验顺序

1. 读头部：`status` 是 `done` 就直接结束，别接着干。
2. 跑 `check`：有硬错误先补齐或退回让交接方重写，别自己猜。
3. 看「坐标」与当前实际是否一致；不一致按第三节处置。
4. 只读「下一步」第 1 条，不预读全部——交接不是路线图。
5. 动手前给三行计划：任务 / 真实状态 / 第一步。

## 六、无意识的失真

三种写的时候最容易犯的：

- **顺序记混**：先做 A 才发现 B 不行，写成了"因为 B 不行才做 A"。无害但影响决策，记不准就别写因果。
- **只记成功**：失败分支被自动省略，接手方重走一遍。这是最贵的一种。
- **把计划写成现状**：「准备改成 X」写成「已改成 X」。写完通读一遍，动词时态对不对。
