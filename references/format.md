# 交接格式

## 一、位置与命名

```
<项目根>/.handoff/<YYYY-MM-DDTHH-mm>_<task-id>.handoff.md
```

- 固定 `.handoff/`，加进 `.gitignore`。
- 本地时间，分钟精度，冒号换成 `-`（Windows 文件名不允许冒号）。
- `task-id` 小写连字符，同一件工作全程不变；换任务换 id。
- 同一任务一条链：`handoff` 递增，`prev` 指向上一条文件名。同一分钟交两次时，工具会加 `-2` 后缀避免覆盖。

```
.handoff/
├─ 2026-11-12T14-05_scan-rules.handoff.md      # handoff: 1
├─ 2026-11-12T17-20_scan-rules.handoff.md      # handoff: 2, prev: ……14-05……
└─ 2026-11-11T09-30_release-notes.handoff.md   # 另一条链
```

## 二、头部字段

| 字段 | 必填 | 取值 | 说明 |
| --- | --- | --- | --- |
| `handoff` | 是 | 整数，从 1 起 | 第几次交接；接链时校验连续性 |
| `task` | 是 | 小写连字符 | 与文件名一致 |
| `created` | 是 | ISO 8601 带时区 | `2026-11-12T17:20+08:00` |
| `repo` | 是 | 绝对路径，正斜杠 | 非代码任务填工作目录 |
| `branch` | 是 | 分支名或 `-` | 非 git 任务填 `-` |
| `head` | 是 | 短 SHA 或 `-` | 非 git 任务填 `-` |
| `status` | 是 | `in-progress` / `blocked` / `review` / `done` | 只描述任务，不描述会话 |
| `prev` | 否 | 文件名或 `null` | 首份填 `null` |

这些字段不是装饰：`head` 填错，漂移检测就失效；`status` 填 `done` 却还有待定项，接方会直接停下。

## 三、六节

顺序固定，标题一字不改——扫读靠位置稳定。

### 1 任务

一句话说清做完是什么样，加一句验收。

```markdown
## 任务
扫描器支持 XAML 与 QML，误报率低于 10%。
验收：三类样例各跑一遍，P0 命中与人工判断逐条对上。
```

不写背景故事、不写价值主张；需要背景就给链接。

### 2 坐标

只放命令输出和看得见的状态。

```markdown
## 坐标
- 分支 `main`，HEAD `ac99bcb`，工作区干净
- `node scripts/slop-scan.mjs examples` → P0 7 · P1 32 · P2 20，退出码 1（预期）
- 端口 49393 上有 web 服务（PID 2044），别关
```

不写「应该没改过什么」。脏文件逐个列出来。

### 3 账

一张三列表，每行一件事。这是和普通清单的区别：**空格子写不下去**。

```markdown
## 账
| 项 | 状态 | 证据 |
| --- | --- | --- |
| 规则表拆成两段 | 已验 | `scripts/slop-scan.mjs:21-60`；`node --test` 12 通过 |
| top-label 改结构识别 | 已验 | before.html 命中 3 处（23/24/32 行） |
| 文档同步 29 条 id | 未验 | 要跑一遍 id 对账，确认差异为 0 |
| 把 P1 也做成退出码 1 | 放弃 | CI 噪音太大，改 `--strict` |
```

- 状态只允许 `已验` / `未验` / `放弃`。
- `已验` 的证据必须能复核：反引号里的路径、命令 + 数字、或一个具体观察。
- `未验` 要写「跑什么才算完」，不能只写「未验证」。
- `放弃` 的条目要在「已排除」里说明为什么。
- 超过 10 行说明任务该拆。

### 4 已排除

```markdown
## 已排除
- 用正则区分「标题上方的标签」和面包屑：两种写法都会误伤，改成看行距和相邻元素
- 把账目做成 YAML：手写麻烦，改回表格
```

写失败现象和原因，不写情绪。真没有就 `- 无`，但先想 30 秒——任何做了两小时的任务，至少否决过一个方案。

### 5 下一步

编号，第一条必须能立刻开始。

```markdown
## 下一步
1. 把 `scripts/slop-scan.mjs:135` 的回看窗口从 3 行改成 2 行，看 before.html 的 top-label 是否仍命中
2. 给 `check` 加 `--strict`，让提醒也返回 1
```

不写「继续完善」「视情况推进」「进一步优化」。若下一步取决于一个待定项，下一步就写「等 X 的决定」。

### 6 边界

三类，能写几类写几类，没有就 `- 无`：

```markdown
## 边界
- 要人定：`.handoff/` 要不要进项目模板？倾向进，但要确认不会误提交
- 只读别动：`references/ai-tells.md`，改规则要同步它
- 外部依赖：GitHub 推送靠 Windows 凭据管理器，环境里没有 token
```

「要人定」是唯一能推给用户的事；自己能决定的不要往这放。

## 四、预算

- 正文（不含头部）**≤ 60 行**，表格每一行都算。
- 单节超过 15 行就该挪：代码进注释，理由进设计文档，数据进附件。
- 交接是一次性的，任务结束整份可以删。它是交接单，不是知识库。

## 五、骨架

`write` 生成的骨架带 `（待填）`，`check` 会直接判失败。填完删干净才算完成。
